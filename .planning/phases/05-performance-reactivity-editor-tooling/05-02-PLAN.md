<objective>
Stop two avoidable costs that grow with slot count and project size: (PERF-03) `DSMSlotManager.GetAllSlots()` re-scans the entire save directory on every call — cache it and invalidate only on slot create/delete; (PERF-04) the UniTask UPM dependency tracks a moving git branch — pin it to an immutable stable release tag so builds are reproducible and can't silently drift.

Purpose: `GetAllSlots()` is called by the Editor window and by key rotation (`RotateEncryptionKeyAsync` enumerates all slots), so on a project with many slots each call does a full `Directory.GetFiles` + extension filter. Caching the result and invalidating it only when the slot set actually changes removes the repeated disk walk. Pinning UniTask stops an upstream branch push from changing this package's behavior between two otherwise-identical checkouts.

Output: a cached `GetAllSlots()` on `DSMSlotManager` (nullable cache field under the existing `_slotsLock`, invalidated in `DeleteSlot` and the new-slot branch of `GetOrCreateSlot`), a pinned `com.cysharp.unitask` line in `package.json`, and an EditMode `DSMSlotManagerCacheTests` covering create/delete correctness + consistency.
</objective>

## Phase Goal (MVP)

**As a** developer running a project with many save slots and a shared UniTask dependency, **I want** slot enumeration to stop re-walking the disk on every call and the UniTask version to be pinned, **so that** the Editor window and key rotation stay fast as slot count grows and my builds are reproducible. MVP slice: a self-contained runtime/dependency-hardening increment — cache-on-first-read, invalidate-on-change, pin-the-dep — with no change to save format, encryption, or slot semantics.
