<objective>
Expose the Phase-4 versioning/migration state and the Phase-2 key-rotation action in the Editor Manager window through NEW, dedicated Editor classes (EDIT-01): a `DSMSlotVersionPanel` that shows each slot's on-disk save version + migration status, and a `DSMKeyRotationPanel` that runs `DSM.RotateEncryptionKeyAsync` behind a confirmation + in-flight guard + visible result. Status is read side-effect-free via a new read-only `DSMSaveInspector`.

Purpose: Phases 2 and 4 added key rotation and versioned migration to the runtime, but the Editor window still can't see a slot's version or trigger a rotation — a developer has no visibility into which saves are stale or a safe way to rotate keys from the tool. This plan surfaces both, without letting a status display accidentally migrate a save or a rotation run unconfirmed.

Output: a read-only `DSMSaveInspector` (decrypt+unwrap → on-disk version, no side effects), a `DSM.CurrentSaveVersion` accessor, two new Editor panel classes composed into the decomposed window, and an EditMode `DSMSaveInspectorTests` fixture.
</objective>

## Phase Goal (MVP)

**As a** developer using the DSM Editor Manager window on a project with encrypted, versioned saves, **I want** to see each slot's save version + whether it needs migration and to rotate the encryption key from the window safely, **so that** I can audit and maintain my saves without hand-editing files or writing throwaway scripts. MVP slice: a vertical editor feature — read a slot's version (read-only inspector) → show version + migration status → offer a guarded rotate-key action → surface the result — end-to-end on the decomposed window.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| on-disk save file → DSMSaveInspector | Corruption/attacker-controlled bytes parsed only to read a version; must not migrate/write/throw |
| Editor user → DSMKeyRotationPanel → DSM.RotateEncryptionKeyAsync | A destructive, atomic, all-slots re-encryption triggered from UI with an operator-entered secret |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Tampering / Data Loss | Version status read accidentally migrating or corrupting a save | high | mitigate | DSMSaveInspector is strictly read-only: TryUnwrap + Decrypt only, no Migrate/Save/WriteJsonToDisk, wrapped in try/catch that returns false. Enforced by the must_haves prohibition + a byte-compare-before/after test. This is the plan's data-safety keystone. |
| T-05-02 | Information Disclosure | The new encryption key leaking into logs, dialogs, or EditorPrefs | high | mitigate | `_newKey` is passed ONLY to RotateEncryptionKeyAsync; grep-enforced that it never appears in Debug.Log*/DisplayDialog strings or EditorPrefs. Error messages mirror DSMEncryptor's value-free style (exception type only). |
| T-05-03 | Denial of Service / Corruption | Double-invoking an in-flight atomic rotation, or dismissing mid-rotation, leaving slots half-rotated | high | mitigate | Rotation is gated behind EditorUtility.DisplayDialog confirmation and a `_rotating` flag that disables the button until the awaited op completes (reset in both success and failure branches). The runtime rotation itself is journal-recovered (Phase 2), so an interrupted rotation self-heals on next load; the UI guard prevents the operator from triggering a second concurrent rotation. |
| T-05-04 | Error Suppression | A rotation failure (DSMRotationInterruptedException / IO) silently swallowed, leaving the operator believing rotation succeeded | medium | mitigate | Every catch branch sets a visible `_lastResult` + Debug.LogError with the exception type; success and failure are distinct visible outcomes (aligns with BUGS-01 visible-errors principle). |

No new package dependency is added; no supply-chain threat. All three high-severity items are fully mitigated by design + tests/guards; no unresolved blocking security checkpoint remains.
</threat_model>
