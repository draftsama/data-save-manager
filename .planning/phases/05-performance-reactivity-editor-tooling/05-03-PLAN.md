<objective>
Break the 825-line `Editor/DSMManagerWindow.cs` god-class into three focused pieces (PERF-01), cache its per-open assembly reflection scan so reopening the window stops re-enumerating every assembly (PERF-02), and replace its exception-swallowing `catch { return null; }` with specific handling that surfaces visible errors (BUGS-01).

Purpose: the window currently rescans `AppDomain.CurrentDomain.GetAssemblies()` for `DSMConstant` defaults every time it opens, mixes UI rendering with reflection and slot I/O in one file, and hides failures behind a bare `catch { return null; }` so a corrupt slot or bad write silently produces nothing. Splitting responsibilities makes the window maintainable and its slot-state logic testable (the base TEST-05 depends on in plan 05-05); caching the scan makes reopening instant; visible errors make failures diagnosable.

Output: a thin `DSMManagerWindow` (lifecycle + `OnGUI` + `Draw*`), a new `DSMConstantReflectionCache` (cached, assembly-reload-invalidated `DSMConstant` scan), a new `DSMManagerSlotOps` (slot discover/load/write/delete/propagate/commit), and specific, logged, user-visible error handling in place of the silent null.
</objective>

## Phase Goal (MVP)

**As a** developer maintaining and using the DSM Editor Manager window, **I want** the window split into focused classes, its reflection scan cached, and its failures made visible, **so that** the window is maintainable and fast to reopen and I can see when a slot operation fails instead of getting a silent empty result. MVP slice: a coherent editor-maintainability increment — one god-class becomes three cooperating classes with the same behavior, a cached scan, and honest error surfacing — landing before the new version/rotate UI (05-04) and its tests (05-05) build on the decomposed structure.
